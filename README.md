# Web3DViewer

.gltf形式の3DモデルをA-Frame を用いてブラウザ上で表示するシステムです。ドラッグ／タッチ操作で3Dモデルを自由に回転・移動・ズームして閲覧できます。

## 公開URL

1つのリポジトリで複数の3Dモデルを公開できます。モデルごとにフォルダを作り、そのフォルダ名がURLになります。

| URL | 内容 |
| --- | --- |
| `https://<ユーザー名>.github.io/<リポジトリ名>/` | モデルの一覧（1つだけの場合はそのモデルへ移動） |
| `…/<モデル名>/` | 3Dビューア |
| `…/<モデル名>/admin` | 管理画面（初期視野・背景色などの設定を変更） |
| `…/<モデル名>/ar-marker/` | マーカー型AR |
| `…/<モデル名>/ar-image/` | 画像トラッキング型AR |

## 特徴

- ドラッグ・ピンチ操作によるモデルの回転／移動／ズーム
- 無操作時の自動回転・視点リセット
- 全画面表示ボタン
- モデル読み込み中のローディング表示
- 単色背景・360°パノラマ画像背景の切り替え
- WebVR（VRヘッドセット）／WebAR（対応スマートフォン）表示への対応（設定でON/OFF切り替え可能）
- スマートフォンの向きに合わせて視点を回転させるジャイロ操作ボタン（対応端末のみ）
- glTFに含まれるアニメーションの自動再生（視点操作中も常に再生され続けます。一時停止／再生ボタンつき）
- **マーカー型AR／画像トラッキング型AR**：マーカーや画像にモデルを現実空間で固定し、周りを歩いて見られます（iOS Safariを含む多くの端末で動作）
- **管理画面**：プレビューを見ながら設定を変更し、そのままGitHubに保存できます
- **表示の固定**：展示中に来場者が別の画面へ移動しないようにする簡易ロック

## ファイル構成

```
├── index.html          モデルの一覧ページ
├── models.json         一覧に表示するモデル（フォルダ名）のリスト
├── viewer/             全モデル共通のビューア本体（通常は編集不要）
│   ├── defaults.js     設定の既定値と、各項目の説明
│   └── …
└── sample/             モデル1つ分のフォルダ（フォルダ名がURLになります）
    ├── config.json     このモデルの設定
    ├── Assets/         このモデルの3Dモデル・画像など
    ├── index.html      入口ページ（編集不要）
    ├── admin/          〃（管理画面）
    ├── ar-marker/      〃（マーカー型AR）
    └── ar-image/       〃（画像トラッキング型AR）
```

## モデルを追加する

1. `sample` フォルダを丸ごと複製し、フォルダ名を公開したいURLの名前に変更します（半角英数字と `-` `_` を推奨。例: `building`）。
2. 複製したフォルダの `Assets` に、3Dモデル（`.gltf` とその関連ファイル、または `.glb`）を入れます。
3. 複製したフォルダの `config.json` の `modelFile` を、そのファイル名に書き換えます。
4. `models.json` にフォルダ名を追加します（一覧ページに表示するため）。

   ```json
   { "models": ["sample", "building"] }
   ```

これで `…/building/` と `…/building/admin` が使えるようになります。

## 設定を変更する

モデルごとの設定は、そのモデルのフォルダにある `config.json` に書きます。`config.json` に書いていない項目は、[`viewer/defaults.js`](viewer/defaults.js) の既定値が使われます（各項目の意味もこのファイルのコメントに書いてあります）。

### 管理画面から変更する

`…/<モデル名>/admin` を開くと、右側のプレビューを見ながら設定を変更できます。

- **初期視野**：プレビューをドラッグして見せたい角度に合わせ、「現在の視点を初期視野にする」を押します。
- **背景色・霧・タイトル・モデルの配置**などは、変更がその場でプレビューに反映されます。
- **「GitHubに保存」**を押すと、`config.json` がリポジトリに直接コミットされ、1〜2分で公開ページに反映されます。
- **「書き出し」**で `config.json` をダウンロードし、GitHubの画面から手動でアップロードすることもできます。

#### 保存に必要なアクセストークン

GitHub Pagesは静的なホスティングのため、保存はブラウザからGitHubのAPIを直接呼び出して行います。初回のみ、次の手順でアクセストークンを発行してください。

1. GitHubにログインし、[Fine-grained personal access tokens の発行ページ](https://github.com/settings/personal-access-tokens/new) を開きます。
2. **Repository access** で「Only select repositories」を選び、このリポジトリだけを選択します。
3. **Permissions → Repository permissions → Contents** を **Read and write** にします。
4. 発行されたトークンを、管理画面の「保存先（GitHub）」→「アクセストークン」に貼り付けます。

> [!IMPORTANT]
> 管理画面のURLは誰でも開けますが、**トークンを持つ人しか保存できません**。トークンはこのリポジトリを書き換えられる鍵なので、他人に教えたり、共用の端末で「記憶する」にチェックを入れたりしないでください（記憶した場合、その端末のブラウザにだけ保存されます）。

### 主な設定項目

| 項目 | 説明 |
| --- | --- |
| `pageTitle` / `displayTitle` | ブラウザタブのタイトル／画面左上に表示する作品タイトル |
| `modelFile` | 表示する3Dモデルのファイル名（`.gltf` / `.glb`）。そのモデルの `Assets` フォルダ内のファイル名のみを指定 |
| `modelPosition` / `modelRotation` / `modelScale` | モデルの初期位置・回転（度）・拡大縮小率 |
| `loadingText` | モデル読み込み中に表示するテキスト（空文字で非表示） |
| `cullBackfaces` | trueで3Dモデルの裏面（法線が逆向きの面）を描画しない |
| `playAnimations` / `animationClip` / `animationLoop` / `animationTimeScale` | glTFアニメーションの再生・クリップ名・ループ方法・再生速度 |
| `enableWebVR` / `enableWebAR` | WebXRのVR／ARボタンの表示可否（対応端末・ブラウザでのみ表示） |
| `enableDeviceOrientation` | ジャイロ操作ボタンの表示可否（モバイルのみ） |
| `enableDisplayLock` | 左上の長押しによる「表示の固定」を使えるようにするか |
| `backgroundType` / `backgroundColor` / `backgroundImage` | 背景の種類（`"color"` / `"image"`）・背景色・360°パノラマ画像（正距円筒図法）のファイル名 |
| `fogColor` / `fogNear` / `fogFar` | 霧の色・距離 |
| `cameraHome` | 初期カメラ位置と注視点 |
| `idleOrbitDelaySec` / `idleResetDelaySec` | 無操作時の自動回転・自動リセットまでの秒数 |
| `autoOrbit` | 無操作時の自動回転の速さ・上下の揺れ幅 |
| `xrCameraPosition` | WebXRのAR/VRモードに入ったときの視点の開始位置 |
| `markerAR` / `imageAR` / `arUI` | マーカー型AR・画像トラッキング型AR・AR画面のボタン類の設定（後述） |

## 表示の固定（展示用の簡易ロック）

展示中に来場者が「戻る」などで別の画面へ移動してしまうのを防ぐ、簡易的なロックです。

- **固定する**：ビューアやAR画面の**左上の角を3秒間長押し**し、解除用のパスワードを決めて入力します。管理画面の「表示の固定」→「このモデルを固定表示で開く」からも固定できます。
- **固定中**：「戻る」・モード切り替え・マーカーARへのボタンが消え、ブラウザの「戻る」でもページを離れません。同じサイトの別のページ（管理画面を含む）を開いても、固定したページへ戻されます。
- **解除する**：同じく左上の角を3秒間長押しし、パスワードを入力します。

> [!NOTE]
> パスワードはそのブラウザのタブ内だけに保持され、どこにも送信されません。**タブやブラウザを閉じると固定は解除されます。** アドレスバーから別のサイトへ移動することまでは防げないため、確実に固定したい場合は端末側の機能（iOSの「アクセスガイド」、Androidの「アプリの固定」など）と併用してください。

## マーカー型AR（現実空間にモデルを固定する）

`<モデル名>/ar-marker/` は、印刷または画面表示した**マーカー**にカメラを向けると、その上に3Dモデルを現実空間に固定して表示します。マーカーの周りを歩いて横から覗き込むこともできます。[AR.js](https://ar-js-org.github.io/AR.js-Docs/) を使用しており、iOS Safari を含む多くの端末で動作します。

> [!IMPORTANT]
> カメラ映像を使うため、**https（GitHub Pages など）で公開したページ**でのみ動作します。`file://` でローカルのHTMLを直接開いた場合や、http のページではカメラが起動しません。

### 使い方

1. スマートフォンで通常ビューアを開き、右下に表示される **「AR / MARKER」ボタン**をタップすると、マーカーARページが開きます。
2. カメラの使用を許可します。
3. マーカーにカメラを向けると、その上にモデルが表示されます。

### マーカーの種類（`config.json` の `markerAR`）

| 設定 | 説明 |
| --- | --- |
| `markerType: "hiro"` | AR.js標準の **Hiroマーカー**。準備不要ですぐ試せます。マーカー画像は [こちら](https://raw.githubusercontent.com/AR-js-org/AR.js/master/data/images/hiro.png) からダウンロードして印刷／別画面に表示してください |
| `markerType: "barcode"` | 番号で識別するバーコードマーカー。`barcodeValue`（0〜63）で番号を指定 |
| `markerType: "pattern"` | 自作マーカー。`patternFile` に `.patt` ファイル名（`Assets` 内）を指定 |
| `modelPosition` / `modelRotation` / `modelScale` | マーカー上でのモデルの位置・回転・大きさ。マーカー中心が原点、マーカー1辺がおよそ1単位です。モデルが大きすぎる場合は `modelScale` を小さく（例: `0.05`）してください |
| `enableButton` | 通常ビューアに「マーカーARで開く」ボタンを表示するか |

**自作マーカー（`.patt`）の作り方**: [AR.js Marker Training](https://ar-js-org.github.io/AR.js/three.js/examples/marker-training/examples/generator.html) に好きな画像をアップロードし、生成される `.patt` を `Assets` に、印刷用マーカー画像を手元に保存します。

### 画像トラッキング（NFT）で任意の画像を使う

マーカーの代わりに、ポスターや作品写真など**任意の画像**をトラッキングして、その上にモデルを固定する方式（NFT = Natural Feature Tracking）も `<モデル名>/ar-image/` として用意しています。マーカーARページ右下の **「画像」ボタン**から切り替えられます（相互に行き来できます）。

ただし、画像をそのまま置くだけでは動きません。**事前に画像を3つの記述子ファイルに変換**する必要があります。設定前は、画像ARページを開くとセットアップ手順の案内が表示されます。

1. **記述子ファイルを生成する**
   - [NFT Marker Creator（Web版）](https://carnaux.github.io/NFT-Marker-Creator/) を開きます。
   - トラッキングしたい画像（**コントラストが高く、特徴の多い画像ほど安定します**。のっぺりした画像やパターンの繰り返しは不向きです。推奨：横幅 数百〜1000px 程度のJPG/PNG）をアップロードします。
   - 「Generate」を実行すると、`<名前>.fset` / `<名前>.fset3` / `<名前>.iset` の3ファイルがダウンロードされます（3つで1セット。ファイル名の共通部分が「記述子名」になります）。
2. **3ファイルをそのモデルの `Assets` フォルダに配置**します。
3. `config.json` の `imageAR.descriptorName`（管理画面の「画像AR」）に、その**記述子名（拡張子を除いた共通部分）**を設定します（例: `poster.fset` などを置いたなら `"poster"`）。

| `imageAR` の設定 | 説明 |
| --- | --- |
| `descriptorName` | 記述子ファイル名（拡張子を除いた共通部分）。空だとセットアップ案内を表示 |
| `modelPosition` / `modelRotation` / `modelScale` | 認識画像の上でのモデルの位置・回転・大きさ。NFTの座標は画像のピクセル基準のためマーカー型とは桁が異なります。ずれる・大きすぎる場合はここで調整（`scale` を数倍〜十数倍、`position` を数十〜百単位にすることがあります） |

> [!NOTE]
> マーカー型（`aframe-ar.js`）と画像型（`aframe-ar-nft.js`）は**排他的な別ビルド**で同じページに同居できないため、2つのページに分け、ボタンで切り替える構成にしています。

### AR画面のUI表示（`config.json` の `arUI`）

AR画面に重ねて表示するボタン類は、`config.json` の `arUI`（管理画面の「AR画面のUI」）で表示・非表示を切り替えられます。展示レイアウトに合わせて隠せます。

| `arUI` の設定 | 説明 |
| --- | --- |
| `showBackButton` | 「戻る」ボタン（通常ビューアに戻る）を表示するか |
| `showModeSwitchButton` | モード切り替えボタン（マーカーAR ↔ 画像AR）を表示するか |
| `showHint` | 画面上部の操作案内テキスト（「マーカーにカメラを向けてください」等）を表示するか |

> [!TIP]
> NFTはマーカー型より認識が不安定で、端末の負荷も高めです。展示で確実性を優先する場合は、まずマーカー型での運用をおすすめします。

## 自分のリポジトリで公開する（GitHub Pages）

コマンド操作は一切使わず、すべてブラウザ上の操作だけで公開できます。GitHubのアカウントを持っていない場合は、事前に [github.com](https://github.com/) で無料アカウントを作成しておいてください。

### 1. プロジェクトのファイル一式をダウンロードする

1. このリポジトリのGitHubページを開きます。
2. 右上あたりにある緑色の **「Code」** ボタンをクリックします。
3. 開いたメニューの一番下にある **「Download ZIP」** をクリックし、ZIPファイルをパソコンに保存します。
4. 保存したZIPファイルを右クリックして展開（解凍）します。`index.html` や `viewer`・`sample` フォルダなどが入ったフォルダができます。

### 2. GitHubに新しいリポジトリを作成する

1. GitHubにログインした状態で、画面右上の **「+」アイコン** → **「New repository」** をクリックします。
2. **「Repository name」** に好きな名前を入力します（例: `my-3d-viewer`）。
3. 公開設定は **「Public」** を選択します（Freeプランでは、Publicなリポジトリでのみ無料でGitHub Pagesを使えます）。
4. 「Add a README file」「Add .gitignore」「Choose a license」は**すべてチェックを入れず**、そのままにしてください。
5. 一番下の緑色の **「Create repository」** ボタンをクリックします。

### 3. ファイルをアップロードする

1. 作成直後のリポジトリページに、「Quick setup」という案内が表示されます。その中にある **「uploading an existing file」** というリンクをクリックします。
   （見当たらない場合は、リポジトリページの **「Add file」** ボタン → **「Upload files」** からでも同じ画面に行けます。）
2. 展開したフォルダの中身（`index.html`、`models.json`、`viewer` フォルダ、`sample` フォルダなど）を**フォルダごとまとめて**、画面中央のアップロード領域にドラッグ＆ドロップします。
   - フォルダごとドラッグすると、サブフォルダの中のファイルも含めて構造を保ったままアップロードできます（Chrome・Edge・Firefoxなどの最新ブラウザで対応）。
   - うまくいかない場合は、アップロード領域内の **「choose your files」** リンクからファイル選択ダイアログを使ってください。
3. ページ下部の **「Commit changes」** の欄はそのままで構いません。緑色の **「Commit changes」** ボタンをクリックすると、アップロードが確定されます。

### 4. GitHub Pagesを有効化する

1. リポジトリページ上部のタブから **「Settings」** を開きます。
2. 左側のメニューから **「Pages」** を選びます。
3. 「Build and deployment」の **「Source」** が **「Deploy from a branch」** になっていることを確認します。
4. その下の **「Branch」** で、ブランチを **「main」**、フォルダを **「/ (root)」** に設定し、**「Save」** をクリックします。

### 5. 公開されたページを確認する

1. 1〜2分ほど待ってから、もう一度「Settings」→「Pages」の画面を開き直します。
2. ページ上部に緑色の帯で **「Your site is live at https://〈あなたのアカウント名〉.github.io/〈リポジトリ名〉/」** と表示されていれば公開完了です。
3. そのURL、または **「Visit site」** ボタンからアクセスすると、ブラウザ上で3Dビューアが表示されます。設定の変更は `…/sample/admin` から行えます。

### 6. 公開後にモデルや設定を変更する

- **設定の変更**：`…/<モデル名>/admin` の管理画面から行えます（「設定を変更する」の節を参照）。GitHubの画面で `config.json` を開き、鉛筆アイコンから直接書き換えることもできます。
- **モデルの追加・差し替え**：「モデルを追加する」の節の手順で、フォルダを「Add file」→「Upload files」からアップロードしてください。

> [!NOTE]
> GitHubには1ファイルあたり25MBまでという制限があります。3Dモデルのファイルサイズが大きい場合は、Blender等のエクスポート時にテクスチャ解像度やポリゴン数を落とすなどして、事前に軽量化してください。
